Звіт: [Венчак Ілона ТК-31.docx](Венчак%20Ілона%20ТК-31.docx) · [PDF](Венчак%20Ілона%20ТК-31.pdf)

## 2. Ідея

Предметна область — LMS на PostgreSQL 16 (схема `lms`, 19 таблиць, файли `sql/00–08` з попередньої роботи без змін).
Нова вимога: **незмінні версії курсу**. Когорта навчається за версією програми, з якою стартувала, навіть якщо курс потім змінили.

- **MongoDB:** колекція `course_versions`, 1 документ = 1 версія (модулі → уроки → матеріали + завдання вкладено), `$jsonSchema`-валідатор, унікальний індекс `(courseId, version)`.
- **PostgreSQL:** ті самі дані у 5 таблицях (`course_versions`, `module_versions`, `lesson_versions`, `material_versions`, `assignment_versions`), тригер незмінності, `cohorts.course_version_id`.
  `09c` додає цикл через процедури: `sp_release_course_version` → `sp_reopen_course` → нова версія; когорта автоматично отримує останню версію; прогрес, здачі робіт і завершення навчання рахуються за версією когорти.
- **Neo4j:** граф пререквізитів `(:Course)-[:REQUIRES]->(:Course)`, CRUD, обходи, `shortestPath`.

## 3. Структура

```
docker-compose.yml   PostgreSQL 16, MongoDB 7, Neo4j 5 (однакові ліміти для PG і Mongo: 2 CPU, 3 GB, кеш 1 GB)
run_all.sh           повний прогін: схема → дані → Mongo → бенчмарк → Neo4j
sql/                 00–08 — попередня робота; 09, 09b — версії; 09c — цикл версіонування; 09d — демо
python/              генерація даних, завантаження в Mongo, бенчмарк, Neo4j
results/             результати full-прогону: results.md/json, benchmark.png, plans/, large_pool/, neo4j_demo.md
```

## 4. Як запустити

Потрібно: Docker Desktop (у Settings → Resources виділити ≥ 8 ГБ RAM), Python 3.

```bash
./run_all.sh smoke   # швидка перевірка, 1–2 хв
./run_all.sh full    # основний прогін для звіту (20 000 версій)
```

`run_all.sh` ставить `00`, `09`, `09b`. Цикл версіонування і демо застосовуються окремо (через stdin, бо `psql` працює в контейнері):

```bash
docker compose exec -T postgres psql -U postgres -d lms -v ON_ERROR_STOP=1 < sql/09c_versioning_workflow.sql
docker compose exec -T postgres psql -U postgres -d lms < sql/09d_demo.sql
```

`09d` виконується в одній транзакції й закінчується `ROLLBACK`, тож дані бенчмарка не змінює.
Для чистого старту: `docker compose down -v` (видаляє томи з даними).

## 5. Головні результати

Медіана, мс; числа з [results/results.md](results/results.md) (основний пул, 1 000 ключів) і [results/large_pool/results.md](results/large_pool/results.md) (пул на весь набір).
Критерій переваги, зафіксований до вимірювань: медіана краща ≥ 1,2× і p95 не гірший; інакше — паритет.

| Сценарій | Варіант | Основний | large_pool |
|---|---|---|---|
| Читання структури версії | SQL + збирання в Python | 0.68 | 0.67 |
| | MongoDB `find_one(_id)` | 1.05 | 0.92 |
| | SQL jsonb (збирання на сервері) | 1.43 | 1.44 |
| Прогрес когорти | SQL за версією, готовий `lesson_count` | 0.52 | 0.53 |
| | SQL, поточна `v_enrollments` | 1.36 | 1.34 |
| | гібрид PG + Mongo | 1.36 | 1.02 |
| Запис версії | SQL без аудиту | 12.93 | 13.35 |
| | SQL з аудитом | 16.57 | 16.94 |
| | Mongo `insert_one` (j=true), лише запис | 1.25 | 1.42 |
| | Mongo наскрізно (читання PG + збирання + insert) | 14.23 | 14.30 |
| Дифф двох версій | SQL `FULL JOIN` | 0.37 | 0.41 |
| | Mongo: 2 документи + дифф у Python | 1.04 | 1.46 |
| Конкурентне читання, 8 потоків | SQL + збирання | 3.28 | 3.59 |
| | MongoDB `find_one(_id)` | 2.87 | 2.94 |
| Розмір на диску | PostgreSQL (5 таблиць + індекси) | 683.7 МБ | 687.8 МБ |
| | MongoDB (стиснуто) | 95.6 МБ | 95.7 МБ |

- Прогрес за поточною структурою відрізняється від прогресу за версією когорти у **31.3%** зарахувань (1566 з 5000).
- Neo4j проти рекурсивного CTE (глибина ≤ 6, 100 курсів): CTE 0.59 мс, Neo4j 2.85 мс ([results/neo4j_demo.md](results/neo4j_demo.md)).

Детальна інтерпретація — у звіті, розділ 5.

## 6. Обмеження

Обидві бази працювали на одному вузлі в Docker на ноутбуці; холодний кеш і реплікацію я не тестувала (`large_pool` лише розширює набір ключів). Зміни між версіями в тестових даних вносив генератор прямими запитами з вимкненими тригерами, тому 31.3% — наслідок саме цих змін, а не статистика реальної платформи. Різниця в розмірі майже повністю через штучний текст уроків (md5, повторений 12 разів): без стиснення колекція займає 549.3 МБ. Запис у MongoDB вимірювався в колекції без валідатора. Тотожність даних SQL ↔ Mongo перевірялася вибірково (60 версій). У `09c` лишаються відомі обмеження: видалене під час редагування завдання блокує завершення старої когорти, `sp_grade` порівнює з поточним `max_score`, а поки курс у draft, зарахування закрите.
